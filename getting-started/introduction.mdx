## Two ways to write and publish

Choose the workflow that fits the team. Writers can move quickly in the visual editor, while engineers keep full control with MDX, Git, branches, and previews.

<Tabs>
  <Tab title="Web Editor" icon="edit-3">
    The [Web Editor](/write-and-publish/web-editor) gives non-technical contributors a visual, in-browser experience with slash commands, live previews, and built-in AI assistance with no code or Git knowledge required.

    <Callout kind="tip" collapsed="false">
      Best for non-technical contributors and teams that want a visual editing experience.
    </Callout>
  </Tab>

  <Tab title="Code Editor" icon="code">
    For engineering teams, the [Code Editor](/write-and-publish/code-editor) workflow keeps docs versioned alongside your codebase. Work in MDX, use your own linters and review tools, and merge documentation changes through the same pull requests as code.

    <Callout kind="tip" collapsed="false">
      Best for engineering teams that want full Git integration and CI control.
    </Callout>
  </Tab>
</Tabs>

Both workflows stay fully in sync. A page edited in the web editor is immediately available in the code editor, and vice versa. Use [branches and previews](/write-and-publish/branches-and-previews) to review changes before they go live, and bring AI coding agents like [Cursor](/write-and-publish/cursor) or [Claude Code](/write-and-publish/claude-code) into the loop for faster authoring.
