## Two ways to work

Documentation.AI supports two fully synced workflows. Pick the one that matches how you already work, and switch when your team needs a different approach.

<Tabs>
  <Tab title="Web Editor" icon="edit-3">
    Write in a visual workspace with built-in editing tools, slash commands, and AI help close at hand.

    <Callout kind="tip" collapsed="false">
      Best for teams who want a guided editing experience in the browser. See the [Web Editor guide](/write-and-publish/web-editor).
    </Callout>
  </Tab>

  <Tab title="Code Editor" icon="code">
    Manage docs as MDX in your codebase, use your preferred editor, and keep documentation inside your existing development workflow.

    <Callout kind="tip" collapsed="false">
      Best for teams that version docs with code and work heavily in local tooling. See the [Code Editor guide](/write-and-publish/code-editor).
    </Callout>
  </Tab>
</Tabs>

## API documentation and playground

Documentation.AI includes a full workflow for publishing API reference material. You can generate docs from schemas, organize endpoints clearly, and let readers try requests without leaving the page.

<Steps>
  <Step title="Import schemas" icon="download" title-type="p">
    Import OpenAPI and JSON schemas to generate API reference pages faster. See [OpenAPI Import](/api-documentation-and-playground/openapi-import).
  </Step>

  <Step title="Organize endpoints" icon="folder-tree" title-type="p">
    Group and structure your API reference so readers can find the right endpoint without digging. See [Organize and Playground](/api-documentation-and-playground/organize-api-reference).
  </Step>

  <Step title="Enable the playground" icon="flask-conical" title-type="p">
    Turn your reference into a working experience by letting readers test requests directly from the docs.
  </Step>
</Steps>
