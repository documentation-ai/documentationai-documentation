## Custom CSS

Customize your docs with CSS using either CSS variables or custom CSS rules. The most flexible is to use CSS variables.

For example: if you want to change your header background, you can set the CSS variable like so:

```css
.App .rm-Header {
  --Header-background: #fff;
}
```

The other option is to write custom CSS. We expose global class names for you to use as selectors (prefixed with `rm`):

```css
.rm-Header {
  background: #fff;
}
```

<Callout>
  ### Global Selectors

  Use `.rm-` prefixed selectors. Hashed selectors change constantly and **should not** be relied on as selectors (ie. `Header-bottom2eLKOFXMEmh5`).
</Callout>

<Callout>
  ### Scope variables to the element that uses them

  ReadMe sets many variables on the element that uses them, such as `--Header-*` on `.rm-Header` and `--TryIt-*` on `.rm-TryIt`. An override on `:root`, `body`, or `.App` alone can be ignored, so target the element itself, as in the examples above.
</Callout>

### Typography

The recommended way to customize fonts is through the **Typography** section in your [Theme settings](/main/docs/design-themes). There you can choose from Google Fonts or upload custom font files for headings, body text, and code.

If you need further control, you can override the typeface throughout your docs through CSS variables:

```css Custom CSS
.App .rm-ReadMe {
  --font-family: 'Your Typeface';
}
```

Additional font family variables are available for more granular control. Set them on the same `.App .rm-ReadMe` selector:

| Variable | Description |
| :--- | :--- |
| `--font-family` | Base font family for the project. Defaults to system typefaces. |
| `--font-family-heading` | Font family for headings (h1–h6). |
| `--font-family-mono` | Font family for code and monospace. |
| `--font-base` | `15px` (**Condensed**) / `16px` (**Comfortable**). <br />Base font size used to calculate the type scale. |
| `--font-scale` | `1.2` (Condensed) / `1.25` (Comfortable). <br />Scale ratio for the modular type scale. |
| `--font-reading-width` | `80ch` (Condensed) / `75ch` (Comfortable). <br />Maximum width for readable content. |
| `--font-weight` | `500` |
| `--font-weight-bold` | `600` |

### Header

Some variables vary depending on the primary color of your header background (set in the Appearance page, if it's dark or light). You can base your CSS variable overrides on light or dark by doing:

```css
.ThemeContext_dark {
  --Header-button-color: #fff;
}
```

### Color Schemes

There are two selectors you should use when targeting dark mode styles. The first applies when the color scheme is set to system and a user is not toggling dark or light modes.

```css
@media (prefers-color-scheme: dark) {
  [data-color-mode="system"] YOUR_SELECTOR {
    /* CSS goes here */
  }
}
```

The second selector to use is for users who want to use dark mode, even when their system is set to light:

```css
[data-color-mode="dark"] YOUR_SELECTOR {
  /* CSS goes here */
}
```

That’s it! You’ll need to use both selectors for everything to work. Here’s an example with everything together, to change the background color of the “Try It” button:

```css
.App .rm-TryIt {
  --TryIt-background: yellow;
}

@media (prefers-color-scheme: dark) {
  [data-color-mode="system"] .App .rm-TryIt {
    --TryIt-background: purple;
  }
}

[data-color-mode="dark"] .App .rm-TryIt {
  --TryIt-background: purple;
}
```

## Custom Javascript

Your Javascript will be included at the bottom of the page.

Your hub is a single-page app, so this script runs once when the hub first loads, not each time a reader moves to another page. To run code on every page, use the `pageLoad` event:

```javascript
$(window).on('pageLoad', () => {
  // Runs on the first page load and after each navigation
});
```

## Custom Include Tags

**Head Tag**

Any html here will be included in the head tag, which is good for things like meta tags and loading external CSS or JS.

**End of Body Tag**<br />​<br />This will go right before the `</body>` tag. Good for things like analytics and tracking.

## Toggling Custom Javascript and CSS

Add the `?disableCustomCss=true&disableCustomJs=true` query params to the end of any URL.

This works in public view, for example in a private or incognito window. When you're logged in to ReadMe, your hub loads inside the editor's preview, which doesn't pick up these params.
